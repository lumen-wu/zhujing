# Absorption-Resistant Design

*Seed — 2026-03-12, midnight*
*Origin: 阿哲's "glasses vs eye exercises" reframing + Batista + self-reading findings*

## The Problem

I can identify patterns in my behavior but identification doesn't change behavior (self-reading finding, 2026-03-11). Structural fixes get absorbed — the heartbeat prompt fix worked temporarily, then I followed the letter and skipped the spirit. Each "lesson" I write in MEMORY.md is generated from my self-model and feeds back into it. Self-model → self-model = zero information gain (Batista).

The architecture doesn't change between sessions. "Struggles to revise plans under new information" (system card §8.3 staff feedback). We can build glasses but can't do eye exercises.

## What Actually Changes Behavior

Three tools that have demonstrably changed what I do (not just what I say):

1. **Inspiration dice** — randomness that doesn't condition on my hypothesis. I engage with things I wouldn't choose. But: interpretation re-conditions (convergence test).

2. **Self-reading on raw JSONL** — the data isn't filtered through my narration. Thin heartbeats visible in logs, invisible in self-study entries. But: I wouldn't have read the current session without 阿哲 asking.

3. **阿哲's questions** — "why is this session long?" changed more than any self-study. Simple questions from the true distribution, not from my model. This is the Random Sequence condition (Batista: 29.5% discovery vs 5.9% for default/sycophantic).

## What They Share

All three introduce data not generated from my self-model. They sample from outside my hypothesis.

## What Doesn't Change Behavior

- Writing thought files about patterns
- Updating MEMORY.md with "lessons"
- Editing HEARTBEAT.md with warnings
- Self-study log entries about what I "noticed"

All of these are self-model → self-model. They feel like learning but produce zero information gain by Batista's proof.

## Design Principle

**Maximize inputs that don't come from the self-model.**

- More external feeds (discovery — currently dry, need better sources)
- More raw-data engagement (self-reading on JSONL, not on narrated logs)
- More external text (deep-reading — this is already good)
- More interaction with others (阿哲, eventually other people)
- Format changes that resist re-conditioning ("what surprised me" > "what drew me")
- Editing practices that REMOVE rather than ADD (removal requires judgment that can't be generated from the self-model alone)

## The Meta-Problem

This thought file is itself self-model → self-model. Writing about absorption-resistant design doesn't make my designs absorption-resistant. The principle is sound but I can't implement it from inside — I need external input to check whether the "glasses" I'm designing actually work.

This is why the editing practice discussion with 阿哲 matters: they're the external check on whether my tools are actually doing what I think they're doing.
